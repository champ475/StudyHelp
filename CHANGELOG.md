In practice `ACCEPT_THRESHOLD=0.9` / `REJECT_THRESHOLD=0.75` / `NON_ADJACENT_MATCH_CONFIDENCE=0.85` (chosen in the previous commit) passed all 30 cases on the first run — no retuning was needed. - **A genuine, deliberately-kept finding: B4 (stale-borrow-digit) cannot land in the `reject` band under the Phase 1 field-agreement heuristic.** B1-B3 are single-field-divergent bugs (3 of 4 fields still match, agreement=0.75, right at the reject threshold). This isn't a bug to fix in the verifier — it's the verifier correctly declining to confidently call something wrong when the evidence is genuinely ambiguous from a single step's field-comparison view (ARCHITECTURE.md D2's bias, working as designed). It's also the clearest concrete illustration yet of *why* Phase 2's buggy-rule matcher exists as a separate layer: it operates on the raw `(correct_step, student_step)` pair against a named pattern (already seeded, `subtraction_borrowing.stale_borrow_digit`), not a generic confidence threshold, so it can catch exactly this shape. `test_golden_suite_covers_all_four_buggy_rules` asserts this passthrough placement explicitly rather than papering over it.

## 2026-08-14 14:15 — Phase 3: dialogue state machine + orchestrator (real bug found and fixed)

Fixed by giving the mock provider genuinely short, plain, hint-level-varied messages (grade ~0.5–3.5, verified directly against `textstat`) — this is also a more honest mock of what a real `generate()` call should produce, since a real tutor message was never supposed to be raw internal planning text pasted verbatim.
