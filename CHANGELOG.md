- **On threshold tuning, stated honestly:** the plan anticipated "expect iteration" here. In practice `ACCEPT_THRESHOLD=0.9` / `REJECT_THRESHOLD=0.75` / `NON_ADJACENT_MATCH_CONFIDENCE=0.85` (chosen in the previous commit) passed all 30 cases on the first run — no retuning was needed. Recorded as a real outcome, not claimed retroactively as "tuned."
- **A genuine, deliberately-kept finding: B4 (stale-borrow-digit) cannot land in the `reject` band under the Phase 1 field-agreement heuristic.** B1-B3 are single-field-divergent bugs (3 of 4 fields still match, agreement=0.75, right at the reject threshold). B4 is inherently two-field-correlated — using the stale pre-decrement digit changes both `minuend_digit` and the resulting `result_digit`, dropping agreement to 0.5, squarely in the `passthrough` band. This isn't a bug to fix in the verifier — it's the verifier correctly declining to confidently call something wrong when the evidence is genuinely ambiguous from a single step's field-comparison view (ARCHITECTURE.md D2's bias, working as designed). It's also the clearest concrete illustration yet of *why* Phase 2's buggy-rule matcher exists as a separate layer: it operates on the raw `(correct_step, student_step)` pair against a named pattern (already seeded, `subtraction_borrowing.stale_borrow_digit`), not a generic confidence threshold, so it can catch exactly this shape. `test_golden_suite_covers_all_four_buggy_rules` asserts this passthrough placement explicitly rather than papering over it.

## 2026-08-14 14:15 — Phase 3: dialogue state machine + orchestrator (real bug found and fixed)

- **Real bug caught by testing, not shipped:** the first implementation didn't persist anything when the timing policy decided not to intervene yet, which meant `AFTER_NTH_REPEAT` could never reach its threshold — every subsequent call saw empty state and reset the count to 1, so the policy silently never triggered. `test_after_nth_repeat_policy_waits_for_the_second_wrong_attempt` failed on first run, exposing this immediately. Fixed by giving the mock provider genuinely short, plain, hint-level-varied messages (grade ~0.5–3.5, verified directly against `textstat`) — this is also a more honest mock of what a real `generate()` call should produce, since a real tutor message was never supposed to be raw internal planning text pasted verbatim.
- Added `fakeredis` as a dev dependency (D29) — gives real state-machine test coverage despite no local Redis in this sandbox, rather than 100% of dialogue tests skipping the way Postgres-dependent ones do.
- 15 new tests (34 dialogue tests total, 158 unit+golden overall): state store round-trips/isolation (5), orchestrator state-machine coverage (8) — no-op, immediate intervention, `AFTER_NTH_REPEAT` threshold (the bug-catching case), correct-retry resolution, turn-budget escalation with worked-example content verified, consecutive-count reset on a different step, gate-rejection fallback, and misconception context reaching the decide call.
